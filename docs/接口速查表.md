# 动物园综合管理系统——统一接口速查表

> 用途：三人开发、联调、合并时统一接口与公共规则。  
> 标记：A = 动物与健康；B = 饲养与物资；C = 游客与票务；共同 = 三人共同维护。
> C相关内容已按2026-11-19实际实现同步；A、B接口及格式沿用原文，本次未逐项复核

---

## 1. 三人分工总表

| 同学 | 子系统         | 主要负责内容                                         | 主要数据文件                                                |
| ---- | -------------- | ---------------------------------------------------- | ----------------------------------------------------------- |
| A    | 动物与健康管理 | 动物档案、园区、动物状态、体检、疾病、治疗、康复     | `animals.txt`、`zones.txt`、`medical_records.txt`           |
| B    | 饲养与物资管理 | 食物库存、喂养计划、喂养记录、库存预警               | `foods.txt`、`feeding_plans.txt`、`feeding_records.txt`     |

## 5.10 数据结构与业务约定

| 定义位置 | 主要类型 |
| --- | --- |
| `visitorcommon.h`、`session.h` | `Money = long long`，单位为分；`Role`、`TicketType`、`TicketStatus`、`CouponStatus`、`FeedbackType`、`FeedbackStatus`、`PurchaseItem` |
| `ticketmanager.h` | `PurchaseRequest`、`PurchasePreview`、`AvailabilityInfo`、`OrderQuery`、`DailyStatistics` |
| `order.h` | `Order`、`OrderItem`、`AdmissionTicket`、`OrderSummary`、`OrderDetail`、`RefundRecord`、`CheckInRecord` |
| `ticketcatalog.h` | `TicketInfo`、`HolidayRule` |
| `couponmanager.h`、`feedbackmanager.h`、`routemanager.h` | `Coupon`、`Feedback`、`FeedbackQuery`、`Route`、`RouteStop`、`RouteDetail` |

- 初始成人票50元、学生票25元、儿童票20元，默认每日容量1000，管理员可调整票价、上下架和指定日容量
- 可购今天至未来第30天的票，一单同一游玩日期、合计1至10张，每张电子票独立保存状态和实付金额
- 普通日可选择会员九折或一张5元券，二者不叠加；券仅抵扣一张基础票价不少于5元的票，退款不返券
- 节日按游玩日期判断，全部票种八折，不叠加会员或优惠券，每张票按分折算并舍去不足一分后合计
- 管理员入口15维护节日规则，年、月、日分别输入，年份0表示每年同一公历月日；重叠规则只折扣一次，年度2月29日仅在有效闰日命中
- 预览只计算；确认购买后生成订单、购买明细和独立电子票，并记录购买时的会员及节日优惠标记
- 退款以电子票编号列表调用，支持同一订单部分退款，仅未使用且游玩日期晚于今天的票可退；按单票历史实付金额退还
- 检票由管理员按电子票编号列表执行，仅游玩当日可用，已使用或已退款票不可重复检票
- 管理员统计中，容量和销量按游玩日期；付款、退款、检票按实际发生日期统计，收入金额为整数分
- 登录游客可提交建议；游后评价需该游客实际检票入园，评分1至5，每个游览日期限一次；管理员可回复并更新处理状态
- 路线为三条预设路线，调用A的只读接口，按实际展出状态跳过不可游览站点；C与B通过总菜单和统一保存连接，无直接库存联动
- 当前账号密码为课程演示用明文保存，不使用密码哈希；注销保留历史资料，存在当天及未来待使用门票时不能注销
- 管理员登录只用于C模块权限，不表示A、B菜单已接入统一权限；未实现充值、真实支付、二维码或联票优惠

# 7. 全局统一规则

| 项目           | 统一规则                                | 负责人 |
| -------------- | --------------------------------------- | ------ |
| 文件字段分隔符 | `|`                                     | 共同   |
| 日期格式       | `YYYY-MM-DD`                            | 共同   |
| 时间格式       | `HH:MM`                                 | 共同   |
| 完整时间格式   | `YYYY-MM-DD HH:MM:SS`                   | 共同   |
| 菜单返回       | `0 = 返回上一页`                        | 共同   |
| 菜单返回       | `M = 返回主菜单`                        | 共同   |
| 菜单返回       | `Q = 退出系统`                          | 共同   |
| 普通修改类接口 | 成功 `true`，失败 `false`               | 共同   |
| 多条查询结果   | `vector<T>`                             | 共同   |
| 单条查询结果   | `bool + out参数`                        | 共同   |
| 跨模块查询接口 | 尽量加 `const`                          | 共同   |
| 文本字段       | 不能包含 `|`、`\r`、`\n`                | 共同   |
| ID 字段        | 不能为空、不能包含空白、不能包含 `|`    | 共同   |
| 数据修改       | 各子系统只修改自己负责的数据文件        | 共同   |
| 跨模块数据     | 通过 Manager 接口访问，不直接读对方文件 | 共同   |

# 13. C 当前文件格式

文件位于 `data/`，统一UTF-8、竖线分隔；下列字段按实际保存顺序列出，金额均为整数分，布尔值0或1
表内字段按保存顺序列出，实际文本使用普通竖线分隔

| 文件 | 字段格式 |
| --- | --- |
| `visitors.txt` | `visitorid\|username\|password\|nickname\|member\|active` |
| `ticket_types.txt` | `type\|price\|onsale`，type为adult/student/child |
| `holiday_settings.txt` | `year\|month\|day`，year为0表示每年 |
| `coupons.txt` | `couponid\|visitorid\|amount\|expirydate\|issuedat\|status\|ticketid\|usedat` |
| `orders.txt` | `orderid\|visitorid\|visitdate\|createdat\|totalprice\|memberdiscount\|holidaydiscount` |
| `order_items.txt` | `itemid\|orderid\|type\|quantity\|unitprice` |
| `tickets.txt` | `ticketid\|itemid\|paidprice\|status\|couponid` |
| `refund_records.txt` | `recordid\|batchid\|ticketid\|operatorid\|amount\|refundedat` |
| `checkin_records.txt` | `recordid\|batchid\|ticketid\|operatorid\|checkedinat` |
| `capacity_settings.txt` | 首行 `default\|1000`，其后指定日覆盖为 `YYYY-MM-DD\|capacity` |
| `feedback.txt` | `feedbackid\|visitorid\|type\|visitdate\|rating\|content\|createdat\|status\|reply\|operatorid\|handledat` |

`orders.txt`兼容原6字段行，缺少末尾节日标记时按false读取；保存时写7字段，历史单价、实付和优惠标记不随新票价或节日规则改变
订单、明细、电子票分别保存，不合并；退款和检票记录引用电子票编号，优惠券及反馈也会做关联校验
可选字段的缺省占位以保存实现为准，例如电子票未用券时couponid写 `-`，不要自行删除字段
Git初始样本包含3种基础票价、默认容量，其余9个文件为空；`operation_logs.txt`由实际操作生成，不提交个人运行日志或账号记录
这些11个文件必须存在；`CStorage::load()`在临时管理器内加载，全部检查通过才更新正式对象；`save()`按顺序写入，不提供跨文件事务回滚
当前不使用 `users.txt`，预设管理员在登录逻辑中处理，游客资料保存在 `visitors.txt`

# 16. Menu 统一接口

| 类              | 负责人 | 接口         |
| --------------- | ------ | ------------ |
| `AnimalMenu`    | A      | `char run()` |
| `HealthMenu`    | A      | `char run()` |
| `InventoryMenu` | B      | `char run()` |
| `FeedingMenu`   | B      | `char run()` |
| `VisitorMenu`   | C      | `char run()` |


C通过 `VisitorMenu` 提供主菜单第5项，`main.cpp`统一保存时调用 `visitorMenu.save()`；游客和票务管理员菜单都在该对象内部，无独立 `TicketMenu`

返回规则统一：

| 返回值 | 含义           |
| ------ | -------------- |
| `'0'`  | 返回上一页     |
| `'M'`  | 返回系统主菜单 |
| `'Q'`  | 请求退出系统   |

# 18. 三人开发时最重要的约定

| 规则                     | 说明                                             |
| ------------------------ | ------------------------------------------------ |
| A 不依赖 B               | `AnimalManager` 不 `#include "FeedingManager.h"` |
| B 可以依赖 A             | B 通过 `const AnimalManager&` 查询动物           |
| C 可以依赖 A             | C 通过 A 的查询接口显示动物和园区                |
| B/C 不直接修改 A 数据    | 不直接写 `animals.txt`                           |
| A 不修改 B 数据          | 不直接写 `feeding_plans.txt`、`foods.txt`        |
| A 不修改 C 数据          | 不直接写订单和门票                               |
| `main.cpp` 不写具体业务  | 只负责创建、加载、菜单跳转、保存                 |
| 公共接口改名必须三人同步 | 避免接口对不上                                   |
